# Визуализатор зависимостей пакетов Ubuntu

Учебная работа по дисциплине «Конфигурационное управление», вариант №13.

## Возможности

Реализована функциональность этапов 1–4 и визуализация пятого этапа:
настройки CLI, загрузка индекса Ubuntu и построение
графа прямых и транзитивных обязательных зависимостей. Используется BFS
с рекурсивным переходом между уровнями, ограничением глубины и защитой
от повторного обхода циклов. Поддерживается тестовый граф из JSON
и поиск его прямых и транзитивных обратных зависимостей.

Получение зависимостей выполняется средствами стандартной библиотеки Python,
без вызова менеджеров пакетов и сторонних библиотек.
Граф сохраняется в DOT, преобразуется в PNG через Graphviz и открывается
стандартным просмотрщиком. Доступно ASCII-дерево. Обратные зависимости
поддерживаются только для тестового репозитория.

Сравнение со штатным инструментом визуализации APT пока не выполнено;
пятый этап в части сравнения остаётся незавершённым.

## Требования и структура

Нужен Python 3. Сборка и дополнительные Python-библиотеки не требуются.
Для создания PNG нужна отдельная программа Graphviz с командой `dot` в `PATH`.

Проверка установки:

```bash
dot -V
```

На macOS при установленном Homebrew:

```bash
brew install graphviz
```

Без Graphviz программа сохраняет DOT и сообщает, что PNG не создан.
Текстовый режим `--no-render` не требует Graphviz. Открытие PNG выполняется
через `open` на macOS, системное приложение Windows или `xdg-open` на Linux.

```text
Pract-2/
├── src/
│   ├── main.py                 # CLI, проверки и вывод
│   ├── repository.py           # Индекс Ubuntu
│   ├── fixture_repository.py   # Тестовый JSON
│   ├── graph.py                # Рекурсивный BFS
│   ├── dependencies.py         # Разбор выражений зависимостей
│   ├── versions.py             # Сравнение версий Debian
│   ├── resolver.py             # Выбор версий и альтернатив
│   └── visualization.py        # DOT, PNG и ASCII-дерево
├── tests/                      # Автоматические проверки
├── examples/repository.json    # Граф с ветвлением и циклом

├── run.sh

```

## Запуск и настройки

Команды выполняются из корня проекта. Справка:

```bash
sh run.sh --help
```

Альтернативный запуск: `python3 -m src.main` с теми же аргументами.

| Параметр | Назначение |
|---|---|
| `--package` | Обязательное имя корневого пакета |
| `--repo` | Обязательный URL индекса или путь к JSON |
| `--mode` | Обязательный режим: `real` или `test` |
| `--pkg-version` | Обязательная точная версия корня в режиме `real` |
| `--max-depth` | Обязательная целая неотрицательная глубина |
| `--ascii` | ASCII-дерево вместо списка связей |
| `--output` | Префикс файлов без расширения: `output/dependencies` |
| `--no-open` | Сохранить DOT/PNG без открытия просмотрщика |
| `--no-render` | Только текст, без файлов и открытия изображения |
| `--reverse` | Обратные зависимости, только в режиме `test` |

В режиме `test` параметр `--pkg-version` также обязателен и проверяется
на непустое значение без пробельных символов, но не используется при обходе:
в JSON нет версий.

## Тестовый репозиторий

Файл `examples/repository.json` содержит:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": ["A"]
}
```

Ключи — имена пакетов из заглавных латинских букв, значения — списки
зависимостей. Каждый упомянутый пакет должен иметь запись, включая пакеты
без зависимостей, например `"E": []`.

```bash
sh run.sh --package A --repo examples/repository.json \
  --mode test --pkg-version 1 --max-depth 3
```

Текстовая часть результата включает общую зависимость `D` и цикл `D → A`:

```text
A: B, C
B: D
C: D
D: A
```

Для демонстрации ограничения глубины повторите команду с другими значениями:

| Глубина | Результат |
|---|---|
| `0` | Только `A: -` |
| `1` | `A: B, C`, затем `B: -` и `C: -` |
| `2` | Дополнительно связи `B: D`, `C: D` и вершина `D: -` |
| `3` | Также ребро `D: A`, без повторного обхода `A` |

При запуске с `--package D --max-depth 1` выводятся `D: A` и `A: -`.
Несуществующий корневой пакет вызывает ошибку, в том числе при глубине `0`.

## Обратные зависимости

Флаг `--reverse` включает поиск пакетов, которые зависят от выбранного.
Режим доступен только для тестового JSON-репозитория; сочетание
`--reverse --mode real` вызывает ошибку.

Программа разворачивает связи всего репозитория, затем использует тот же
рекурсивный BFS с ограничением глубины и обработкой циклов. Исходный
репозиторий не изменяется.

```bash
sh run.sh --package D \
  --repo examples/repository.json \
  --mode test --pkg-version 1 \
  --max-depth 2 --reverse
```

Результат:

```text
D: B, C
B: A
C: A
A: -
```

В обратном режиме строка `D: B, C` означает, что пакеты `B` и `C`
зависят от `D`. При глубине `1` выводятся только прямые обратные зависимости;
при большей глубине — также транзитивные.

Примеры для демонстрации на том же файле:

- `--package D --max-depth 0 --reverse`: только `D: -`.
- `--package D --max-depth 1 --reverse`: `D: B, C`, `B: -`, `C: -`.
- `--package D --max-depth 3 --reverse`: дополнительно сохраняется
  ребро `A: D`, замыкающее цикл без повторного обхода `D`.

Прочерк может означать достижение предельной глубины. Если от пакета
никто не зависит, обратный граф состоит только из корня с прочерком.

## Правила обхода и вывода

Корень имеет глубину `0`. Вершины предельного уровня включаются в граф,
но их зависимости не раскрываются. Прочерк означает отсутствие исходящих
связей в построенном результате: это может быть следствием ограничения
глубины, а не отсутствия зависимостей в репозитории.

BFS обрабатывает весь текущий уровень перед рекурсивным переходом к следующему.
Множество обнаруженных вершин предотвращает повторный обход. Рёбра к уже
обнаруженным вершинам сохраняются, поэтому циклы остаются видны.
В тестовом режиме вершина — имя, в реальном — пара «имя, версия».

## Реальный репозиторий Ubuntu

Пример для индекса Ubuntu `noble`, компонента `main`, архитектуры `amd64`:

```bash
sh run.sh --package bash \
  --repo https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz \
  --mode real --pkg-version 5.2.21-2ubuntu4 --max-depth 1
```

В `--repo` передаётся полный URL файла `Packages` или `Packages.gz`,
а не корень репозитория. Сжатие gzip определяется по содержимому.
Версия корня должна точно присутствовать в выбранном индексе;
исторические версии могут отсутствовать.

Учитываются `Pre-Depends` и `Depends`; `Recommends` и `Suggests` исключены.
Альтернативы через `|` проверяются слева направо. Выбирается первая
альтернатива с доступной подходящей версией, затем её наибольшая версия
по правилам Debian. Поддерживаются ограничения `<<`, `<=`, `=`, `>=`, `>>`.
Вывод имеет вид `имя (версия): зависимости`.

### Ограничения

- Используется один индекс: зависимости из других компонентов или выпусков
  автоматически не загружаются. Отсутствующая зависимость вызывает ошибку.
- Виртуальные пакеты через `Provides` и архитектурные квалификаторы вроде
  `:any` не поддерживаются.
- Выбор версий выполняется отдельно для каждой связи. Полная совместимость
  установки, конфликты и согласование версий всего графа не проверяются.
- Сравнение версий предполагает корректные версии Debian в индексе.
- Очень глубокий граф может превысить ограничение рекурсии Python.
- Индекс полностью загружается и разбирается в оперативной памяти.
- Некоторые ошибки файловой системы при сохранении результатов пока
  не преобразуются в краткое сообщение и могут выводить traceback.

## Визуализация

По умолчанию после списка связей создаются `output/dependencies.dot`
и, если доступен Graphviz, `output/dependencies.png`. Путь к каждому
созданному результату выводится в терминал. PNG автоматически открывается.
Повторный запуск с тем же `--output` перезаписывает файлы.

```bash
sh run.sh --package A --repo examples/repository.json \
  --mode test --pkg-version 1 --max-depth 3 --ascii \
  --output output/example-a --no-open
```

ASCII-часть вывода:

```text
A
|-- B
|   `-- D
|       `-- A [cycle]
`-- C
    `-- D [seen]
```

`[cycle]` обозначает возврат к вершине текущей ветви; `[seen]` — вершину,
уже раскрытую в другой ветви. Для чисто текстового запуска добавьте
`--no-render`: файлы и сообщения об их путях не создаются.
`--no-open` сохраняет файлы, но не открывает окно. Эти флаги не меняют обход.

### Три примера реальных пакетов

Для демонстраций используется один индекс Ubuntu `noble/main`, `amd64`:

```bash
REPO="https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz"

sh run.sh --package bash --pkg-version 5.2.21-2ubuntu4 \
  --repo "$REPO" --mode real --max-depth 1 \
  --ascii --output output/bash

sh run.sh --package gzip --pkg-version 1.12-1ubuntu3 \
  --repo "$REPO" --mode real --max-depth 3 \
  --ascii --output output/gzip

sh run.sh --package coreutils --pkg-version 9.4-3ubuntu6 \
  --repo "$REPO" --mode real --max-depth 3 \
  --ascii --output output/coreutils
```

Каждый запуск создаёт отдельную пару DOT/PNG. Для `bash` выбрана глубина `1`:
при более глубоком обходе встречается виртуальная зависимость `awk`,
разрешение которой пока не поддерживается. В графах видны общие зависимости;
например, у `coreutils` сохраняется цикл `libc6 ↔ libgcc-s1`.
Доступность указанных версий зависит от содержимого выбранного индекса.

### Сравнение со штатными инструментами

Сравнение пока не проводилось. Для завершения пункта 5 пятого этапа нужно
получить графы штатным инструментом APT и сопоставить вершины и связи
при одинаковых источниках, архитектуре, версиях и сопоставимой глубине.

Ожидаемые причины различий: ограничение глубины, один выбранный индекс,
локальный выбор альтернатив и отсутствие поддержки виртуальных пакетов.
Это предположения о причинах, а не результаты выполненного сравнения.

## Основные компоненты

- `AppConfig` хранит настройки; `ConfigParser.parse()` читает и проверяет CLI.
- `UbuntuRepository.from_url()` загружает индекс; `get_dependencies()`
  возвращает группы зависимостей, `get_versions()` — доступные версии.
- `FixtureRepository.from_file()` читает и проверяет JSON;
  `get_dependencies()` возвращает прямые зависимости тестового пакета,
  `reversed()` создаёт репозиторий с обратным направлением связей.
- `parse_dependency_group()` разбирает альтернативы и ограничения.
- `compare_versions()` сравнивает версии; `satisfies_version()` проверяет условие.
- `DependencyResolver` выбирает альтернативы и версии для реальных вершин.
- `DependencyGraph.build()` строит граф рекурсивным BFS.
- `format_node()` и `print_graph()` формируют список связей.
- `to_dot()` формирует DOT; `render_graph()` сохраняет DOT и создаёт PNG.
- `open_image()` открывает PNG; `to_ascii()` формирует дерево.
- `main()` связывает компоненты и обрабатывает `ValueError`.

## Тестирование

```bash
python3 -m unittest discover -s tests -v
```

Отдельная проверка обхода:

```bash
python3 -m unittest discover -s tests -p "test_graph.py" -v
```

Используется `unittest`. Тесты не требуют интернета: CLI-проверки запускают
локальный HTTP-сервер на `127.0.0.1`, проверки загрузчика подменяют ответы
через `unittest.mock`. Проверяются параметры, разбор индекса и JSON,
версии, альтернативы, BFS, глубина, циклы, обратные зависимости
и ASCII-вывод через CLI. CLI-тесты используют `--no-render`, поэтому
не открывают окна и не требуют установленного Graphviz.

Ручная проверка PNG без открытия просмотрщика:

```bash
sh run.sh --package A --repo examples/repository.json \
  --mode test --pkg-version 1 --max-depth 3 \
  --ascii --no-open --output output/check
```

Результаты в `output/` исключены через `.gitignore`: их не следует
добавлять в репозиторий.

Коды завершения:

- `0` — успех;
- `1` — обработанная ошибка проверки, чтения, загрузки или выбора зависимости;
- `2` — ошибка аргументов, обнаруженная `argparse`.
