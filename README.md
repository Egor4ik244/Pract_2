# Визуализатор зависимостей пакетов Ubuntu

Учебная работа по дисциплине «Конфигурационное управление».
Вариант №13.

## Описание

Инструмент для анализа и визуализации зависимостей пакетов Ubuntu.

На текущем этапе реализованы:
- чтение настроек из командной строки;
- проверка параметров;
- загрузка индекса Ubuntu по HTTP/HTTPS;
- чтение текстового `Packages` и распаковка `Packages.gz`;
- поиск пакета по имени и точной версии;
- вывод прямых зависимостей из `Pre-Depends` и `Depends`;
- сохранение ограничений версий и альтернатив через `|`;
- вывод настроек в тестовом режиме.

Транзитивный обход, чтение тестового графа и визуализация пока
не реализованы. Используются только средства стандартной библиотеки;
менеджеры пакетов для получения зависимостей не вызываются.

## Требования

- Python 3.
- Дополнительные библиотеки не требуются.

## Структура проекта

- `src/main.py` — приложение.
- `src/repository.py` — загрузка и разбор индекса Ubuntu.
- `tests/test_cli.py` — тесты командного интерфейса.
- `tests/test_repository.py` — тесты разбора и загрузки индекса.
- `run.sh` — скрипт запуска.

## Запуск

Из корня проекта:

```bash
sh run.sh --package bash \
  --repo https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz \
  --mode real \
  --pkg-version 5.2.21-2ubuntu4 \
  --max-depth 3
```

Пример проверен на индексе Ubuntu 24.04 (`noble`), компоненте `main`,
архитектуре `amd64`. Результат:

```text
Прямые зависимости bash (5.2.21-2ubuntu4):
libc6 (>= 2.38)
libtinfo6 (>= 6)
base-files (>= 2.1.12)
debianutils (>= 5.6-0.1)
```

В `--repo` необходимо передать полный URL конкретного индекса
`Packages` или `Packages.gz`, а не корень репозитория.
Выпуск, компонент и архитектура выбираются путём в URL.
Версия должна точно совпадать со значением `Version` в этом индексе.
Исторические версии могут отсутствовать.

Программа выводит сначала `Pre-Depends`, затем `Depends`.
Каждая строка — группа зависимостей: запятая разделяет группы,
а `|` сохраняет альтернативы. Выбор альтернатив и проверка ограничений
версий зависимостей пока не выполняются. `Recommends` и `Suggests`
не включаются.

Справка:

```bash
sh run.sh --help
```

## Настройки

| Параметр | Назначение |
|---|---|
| `--package` | Имя пакета, обязательный параметр |
| `--repo` | Полный URL индекса или путь к тестовому файлу |
| `--mode` | Обязательный режим: `real` или `test` |
| `--pkg-version` | Версия пакета, обязательный параметр |
| `--ascii` | Флаг ASCII-дерева, по умолчанию выключен |
| `--max-depth` | Обязательная целая неотрицательная глубина |

Параметр `--repo` обязателен в обоих режимах.
Параметры `--ascii` и `--max-depth` принимаются и проверяются,
но пока не влияют на получение прямых зависимостей.
В тестовом режиме они выводятся вместе с остальными настройками.

## Тестовый режим

В тестовом режиме имя пакета состоит из заглавных латинских букв.
Путь должен указывать на существующий доступный для чтения файл.

```bash
sh run.sh --package A \
  --repo examples/repository.txt \
  --mode test \
  --pkg-version 1 \
  --max-depth 2
```

Перед запуском необходимо создать файл `examples/repository.txt`.
На текущем этапе его содержимое не анализируется: выводятся настройки.

## Основные компоненты

- `AppConfig` — хранит настройки приложения.
- `AppConfig.print_summary()` — выводит настройки.
- `ConfigParser` — описывает, читает и проверяет аргументы.
- `ConfigParser.parse()` — возвращает объект проверенных настроек.
- `UbuntuRepository(text)` — разбирает текст индекса.
- `UbuntuRepository.from_url(url)` — загружает индекс и создаёт репозиторий.
- `UbuntuRepository.get_dependencies(package, version)` — возвращает группы
  прямых обязательных зависимостей указанной версии.
- `main()` — управляет запуском и обработкой ошибок.

## Проверки параметров

Программа проверяет:
- наличие обязательных аргументов;
- допустимость режима работы;
- формат имени пакета;
- структуру URL в реальном режиме;
- существование и возможность чтения тестового файла;
- отсутствие пустой версии и пробельных символов в ней;
- целочисленность и неотрицательность глубины.

Коды завершения:
- `0` — успешное выполнение;
- `1` — ошибка проверки, загрузки, разбора или поиска пакета/версии;
- `2` — ошибка разбора аргументов командной строки.

## Запуск тестов

Сборка не требуется.

```bash
python3 -m unittest discover -s tests -v
```

Тесты не требуют интернета. CLI-тесты запускают локальный HTTP-сервер
на `127.0.0.1` со свободным портом и временным индексом.
Тесты репозитория подменяют сетевые ответы через `unittest.mock`.
Проверяются обычный и gzip-индекс, зависимости, версии, некорректные
данные, ошибки загрузки и параметры CLI.
