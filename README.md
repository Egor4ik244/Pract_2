# Визуализатор зависимостей пакетов Ubuntu

Учебная работа по дисциплине «Конфигурационное управление».
Вариант №13.

## Описание

Инструмент для анализа и визуализации зависимостей пакетов Ubuntu.

На текущем этапе реализованы:
- чтение настроек из командной строки;
- проверка параметров;
- вывод настроек в формате ключ-значение.

Получение зависимостей и визуализация пока не реализованы.

## Требования

- Python 3.
- Дополнительные библиотеки не требуются.

## Структура проекта

- `src/main.py` — приложение.
- `tests/test_cli.py` — тесты командного интерфейса.
- `run.sh` — скрипт запуска.

## Запуск

Из корня проекта:

```bash
sh run.sh --package bash \
  --repo https://archive.ubuntu.com/ubuntu \
  --mode real \
  --pkg-version 5.2 \
  --max-depth 3
```

Указанная версия на первом этапе не проверяется на наличие
в репозитории.

Справка:

```bash
sh run.sh --help
```

## Настройки

| Параметр | Назначение |
|---|---|
| `--package` | Имя пакета, обязательный параметр |
| `--repo` | URL репозитория или путь к тестовому файлу |
| `--mode` | Обязательный режим: `real` или `test` |
| `--pkg-version` | Версия пакета, обязательный параметр |
| `--ascii` | Флаг ASCII-дерева, по умолчанию выключен |
| `--max-depth` | Обязательная целая неотрицательная глубина |

Параметр `--repo` обязателен в обоих режимах.
На текущем этапе `--ascii` только сохраняется и выводится.

## Тестовый режим

В тестовом режиме имя пакета состоит из заглавных латинских букв.
Путь должен указывать на существующий доступный для чтения файл.

```bash
sh run.sh --package A \
  --repo examples/repository.txt \
  --mode test \
  --pkg-version 1 \
  --max-depth 2
```

Перед запуском необходимо создать файл `examples/repository.txt`.
На первом этапе его содержимое не анализируется.

## Основные компоненты

- `AppConfig` — хранит настройки приложения.
- `AppConfig.print_summary()` — выводит настройки.
- `ConfigParser` — описывает, читает и проверяет аргументы.
- `ConfigParser.parse()` — возвращает объект проверенных настроек.
- `main()` — управляет запуском и обработкой ошибок.

## Проверки параметров

Программа проверяет:
- наличие обязательных аргументов;
- допустимость режима работы;
- формат имени пакета;
- структуру URL в реальном режиме;
- существование и возможность чтения тестового файла;
- отсутствие пустой версии и пробельных символов в ней;
- целочисленность и неотрицательность глубины.

Коды завершения:
- `0` — успешное выполнение;
- `1` — ошибка проверки значений;
- `2` — ошибка разбора аргументов командной строки.
